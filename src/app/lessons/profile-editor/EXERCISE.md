# Практика 02 — редактор профілю

Адреса: `/profile-lab`. Макет статичний; функціональність реалізує учень.
Перший урок залишається за адресою `/`.

## Основна частина — виконуй послідовно

1. У `ProfileLesson` створи звичайні властивості: `displayName` (string), `role` (string), `bio` (string), `accentColor` (string), `nameSize` (number), `isAvailable` (boolean), `lastContactMessage` (string). Початкові значення бери з макета: «Олексій Мельник», «Frontend Developer», текст опису, `#635bce`, `28`, `true`, «Запитів на контакт ще немає.». Масиви, сервіси та API не потрібні.
2. Імпортуй `FormsModule` у `ProfileLesson` та додай до `imports`. Через `[(ngModel)]` зв’яжи шість полів із відповідними властивостями. Прибери статичні `value`, `checked` та текст усередині textarea, які замінює прив’язка. Залиш `name`, `id` і label. `nameSize` має залишатися числом.
3. У `ProfilePreview` оголоси шість inputs з такими самими назвами через `@Input()` із початковими значеннями. Для цієї вправи використовуй декоратори, щоб закріпити їх. Передай всі шість значень із батька через property binding. Читай звичайні властивості без `()`.
4. Через інтерполяцію виведи ім’я, спеціальність та опис у картці. Статичні ініціали аватара можна залишити. Прив’яжи `accentColor` до фону `.cover` через `[style.background-color]`, а `nameSize` до розміру `.profile-name` через `[style.font-size.px]`. Зміни полів мають відразу відображатися в картці.
5. Через class binding додавай `.available`, коли `isAvailable` дорівнює true, і `.unavailable`, коли false. Прибери постійний клас `available` із HTML. Текст статусу також має змінюватися між «Відкритий до пропозицій» та «Зараз недоступний»; можна використати тернарний вираз в інтерполяції. Через `[disabled]` вимикай кнопку контакту, коли ім’я після `trim()` порожнє або профіль недоступний. Не змінюй батьківські дані з дитини.
6. У батька створи метод `resetProfile()` та підключи до кнопки «Скинути зміни» через `(click)`. Метод має відновлювати шість початкових значень і повідомлення про відсутність запитів. Поля редактора та картка мають оновитися разом.
7. У дитини оголоси `@Output() contactRequested` через `EventEmitter<string>`. Підключи метод до кнопки «Зв’язатися»; метод має емітити поточне ім’я. У батька підпишись на подію через `(contactRequested)`, передай `$event` у свій обробник і онови `lastContactMessage` текстом «Запит на контакт: [отримане ім’я]». Виведи повідомлення в наявному блоці «Остання дія». Дитина повідомляє про дію, батько змінює свій стан.

## Додатково — після основної частини

8. **ngClass / ngStyle:** спочатку перевір class/style bindings із кроків 4–5. Потім заміни прив’язки класів статусу на `ngClass`, а дві прив’язки стилів — на `ngStyle`. Імпортуй `NgClass` і `NgStyle` з `@angular/common` у дочірній компонент та додай до `imports`. Не залишай дві різні прив’язки, які керують тією самою CSS-властивістю. Результат має залишитися таким самим.
9. **Content projection:** перенеси абзац «Мій фокус…» із дитини всередину тегів `app-profile-preview` у батьківському шаблоні. Заміни абзац у `.projected-note` дитини на `ng-content`. Передай довільний власний текст і перевір відображення. Для компонента з вкладеним контентом потрібні відкривальний і закривальний теги. Стилі переданого абзацу належать батьківському компоненту; за потреби задай йому `margin: 0` там.
10. **Lifecycle:** у `ProfilePreview` додай `OnInit`, `OnChanges`, `OnDestroy` та відповідні методи. У hooks лише виводь повідомлення в консоль; у `ngOnChanges` виведи `SimpleChanges`. Перше встановлення прив’язаних inputs викликає `ngOnChanges` перед `ngOnInit`; подальші зміни inputs знову викликають `ngOnChanges`, а не `ngOnInit`. Для `ngOnDestroy` перейди посиланням до уроку 01; повернись і перевір нову ініціалізацію. Таймери та підписки для цієї вправи не створюй.

## Критерії самоперевірки

- Зміна імені, спеціальності й опису відображається без перезавантаження.
- Колір і розмір імені відповідають полям редактора.
- Checkbox змінює текст, класи статусу та доступність кнопки контакту.
- Порожнє або заповнене лише пробілами ім’я вимикає кнопку контакту.
- Натискання активної кнопки передає поточне ім’я батькові та змінює повідомлення.
- Скидання повертає всі поля, картку і повідомлення до початкового стану.
- `npm run build` завершується без помилок.

Не потрібно реалізовувати всі lifecycle hooks: решту розглянемо на окремих прикладах.
